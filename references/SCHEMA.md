# SCHEMA — AI 学习知识库页面规范

> 本文件定义知识库中所有页面的字段与格式规范。新建或更新页面时，必须遵守本规范。
> 配套文档：`INDEX.md`（总索引）、`MAINTENANCE.md`（维护手册）、`使用说明.md`（使用流程）。

## 1. 目录结构

| 目录 | 用途 | 是否可修改 |
|---|---|---|
| `00-收件箱/` | 新生成 / 待确认的草稿（`status: draft` 或 `wip`） | ✅ 仅在此新建 |
| `10-MOC/` | 主题地图（按主题索引笔记），文件名以 `MOC-` 开头 | ✅ |
| `20-笔记/` | 归档后的正式笔记 + 概念笔记（`status: reviewed` 为主） | ✅ |
| `30-素材/` | 原始资料（视频/原网页/原文），**只读区，不改写不删除** | ❌ |
| `90-模板/` | 笔记模板（视频 / 概念 / 通用 / MOC） | ✅ |
| `INDEX.md` / `SCHEMA.md` / `MAINTENANCE.md` / `Home.md` / `使用说明.md` | 治理与导航文档 | ✅ |

> `30-素材/` 相当于「raw 区」：原件原样留存、不可改写，笔记通过 frontmatter 的 `source` 字段指回它实现来源可溯。

## 2. 页面头部（Frontmatter）

每个知识页必须以 YAML 头部开头：

| 字段 | 必填 | 取值 | 说明 |
|---|---|---|---|
| `title` | ✅ | 文本 | 页面显示标题，**也是 WikiLink 的链接名**（见 §4） |
| `type` | ✅ | `note` / `concept` / `moc` / `home` | 页面类型 |
| `source` | ✅ | 路径或链接 | 原始资料位置（`30-素材/...`）或外部链接，保证可溯 |
| `created` | ✅ | `YYYY-MM-DD` | 创建日期 |
| `updated` | ✅ | `YYYY-MM-DD` | 最近更新日期 |
| `tags` | 可选 | 列表 | 标签，如 `[视频笔记, RAG]` |
| `status` | ✅ | `draft` / `wip` / `reviewed` / `archived` | 页面状态（见 §3） |
| `confidence` | 可选 | `高` / `中` / `低` | 信息可信度 |
| `uncertainty` | 可选 | 文本 | 不确定或待核实的内容（诚实优先，见 §5） |
| `related` | 可选 | 列表 | 关联页面名，如 `["RAG检索增强生成入门"]` |
| `moc` | 可选 | 列表 | 所属主题地图，如 `[MOC-AI工具与工作流]` |

示例（通用笔记）：

```yaml
---
type: note
title: "一句话主题"
source: "30-素材/原文件名.md"
created: 2026-09-03
updated: 2026-09-03
tags: [视频笔记, RAG]
status: reviewed
confidence: 中
uncertainty: 预算是否含运维费用待确认
related: ["概念-RAG检索增强生成"]
moc:
  - MOC-AI工具与工作流
---
```

## 3. 状态枚举（统一，全库只有这四种）

| 状态 | 含义 | 常见位置 |
|---|---|---|
| `draft` | 草稿 / 待读，刚落入收件箱或初转写 | `00-收件箱/` |
| `wip` | 撰写中 / 待补充，框架在但内容未齐 | `20-笔记/` 少数 |
| `reviewed` | 已读已消化（**终态**），正常笔记应到此 | `20-笔记/` 绝大多数 |
| `archived` | 过时 / 弃用 / 已转正的收件箱副本 | `00-收件箱/已转正/` |

> ⚠️ 历史曾出现 `完整 / 已完成 / 已整理 / 已补全 / 待补充` 等多种写法，已统一收敛为上述四种。新增页面**严禁**再用旧词。

## 4. 链接与命名规则

- **链接以 `title` 为准，不是文件名**：Obsidian 中 `[[链接名]]` 解析的是 frontmatter 的 `title`，文件名可与之不同（如文件 `沉淀-WorkBuddy对话无法被自动检索.md`，其 `title` 为一句长标题）。
- **改名即断链**：修改某页 `title` 后，必须全库替换所有指向它的 `[[旧title]]`，否则产生断链。
- **文件名全局唯一**，避免重名；概念笔记以 `概念-` 开头，MOC 以 `MOC-` 开头。
- 正文中的相关页面一律用 `[[WikiLink]]` 连接，形成知识网。

## 5. 正文结构约定

- 一级标题（`#`）：页面标题（与 `title` 一致）。
- 主体用二级 / 三级标题组织；术语、概念、相关笔记用 `[[WikiLink]]` 互联。
- **概念笔记**（`type: concept`）固定四段：`## 定义` / `## 核心要点` / `## 应用场景 / 与我的关系` / `## 相关链接`。
- **演进记录**（✅ 必填区块）：**每篇知识页正文必须包含 `## 演进` 区块**。新建笔记时即以 `## 演进 · YYYY-MM-DD` 记一条「初稿」；任何后续补充 / 修正，**追加**新的 `## 演进 · YYYY-MM-DD` 区块（**旧内容不删除**），只标注变化并刷新 `updated`。这让知识"怎么长出来"可回溯，也是知识库可审计性的基础。

## 6. 来源（30-素材 / 外部链接）处理规则

- `30-素材/` 内原件**不改写、不重命名、不删除**。
- 笔记的 `source` 指向原件路径或外链；不确定项记在 `uncertainty`，**绝不写回原件**。
- 新建笔记建议在 `INDEX.md` 登记；收件箱待确认项可在 `INDEX.md` 的「待整理原文」区标注。

## 7. 索引登记

- 所有正式笔记必须在 `INDEX.md` 登记（笔记表 / 概念表）。
- 概念笔记同时在 `概念笔记.md` 与对应 MOC 的「核心概念」区加链。
